# Meme Radar backend

QuickNode mainnet configuration with public RPC fallback: [English](../RPC_PROVIDERS.md) · [简体中文](../RPC_PROVIDERS.zh-CN.md).

Go backend with multiple roles. `radar api` serves [`api/openapi.yaml`](../api/openapi.yaml), using PostgreSQL (`--store=pg`) or a deterministic in-memory mock (`--store=mock`). `radar ingest` and `radar backfill` fetch full blocks over HTTP JSON-RPC. Each chain’s parse process runs protocol decoding and an independent balance pass. `radar compute` derives market data, holdings, list versions and inflow projections; `radar enrich` supplements supply and display metadata. Architecture and consistency boundaries: [technical overview](../TECHNICAL_OVERVIEW.md). Conventions: [AGENTS.md](AGENTS.md).

Go 1.26.5 (`go.mod`). Run from the repository root:

| Command                               | Purpose                                                                                                |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `make -C backend setup`               | Download modules, enable the commit hook                                                               |
| `make -C backend run`                 | Build and start `bin/radar api --store=mock` on `RADAR_API_ADDR` (default 127.0.0.1:8080)              |
| `make -C backend check`               | fmt-check → vet → build → test → binary smoke                                                          |
| `make -C backend test-race`           | Race tests                                                                                             |
| `make -C backend db-up` / `db-down`   | Start/stop the local PostgreSQL container `meme-radar-app-pg` (127.0.0.1:55432, user/password `radar`) |
| `make -C backend test-db`             | Start the database and run all tests including PostgreSQL integration tests, race-enabled              |
| `make -C backend ingest CHAIN=solana` | Build and follow one chain (`solana`, `base`, `bsc`) into the local database                           |
| `make -C backend bench` / `profile`   | Inflow first-query benchmark; CPU/memory pprof into `.local/profile/`                                  |
| `make dev-connected`                  | Go API plus the frontend dev server proxying `/api/v1` to it                                           |

Configuration: `--addr`, `--store=mock|pg`, `--debug-addr` (pprof, loopback only, off by default); `RADAR_ADMIN_TOKEN` guards `/api/v1/admin/*` (the mock store defaults it to `mock-admin`).

Optional bounded read cache: `radar api --store=pg --read-cache-max-age=1s` keeps health and token-detail observations for at most one second. The default `0` preserves uncached reads. Active keys refresh in the background with bounded concurrency; expired observations return an error when PostgreSQL cannot refresh them. `X-Data-As-Of` preserves the actual PostgreSQL transaction observation time, excluding waits before query dispatch. `X-Data-Age-Ms` exposes its age; the frontend proxy recomputes age after receiving the full response and reserves 10ms for the final local socket delivery. The API leaves 20ms for local API/proxy handoff while preserving the original timestamp. The JSON `as_of` field keeps its existing endpoint meaning. Health/detail reserve a separate read-only pool of at most four additional connections; replacement sessions are prepared before use and bulk work retains its ordinary pool. Startup prepares protocol statements without executing dummy queries or priming token responses, and initializes the singleton health report before accepting requests. The health report stays active while the service is idle. Every health refresh validates a SHA-256 signature of all50 failure values and retry states in PostgreSQL. Unchanged failure payloads are reused only after that current check; changes and deletions return fresh values in the same batch. Pending parser totals and open-gap reason counts use exact counters updated in the same writer transaction; bulk insert/delete transitions aggregate by chain and reason, and 64 shards disperse counter writes. Rollbacks and reorg deletions preserve exact totals. Token detail derives its cutoff and symbol inside one repeatable-read batch to avoid a second network wait; a bounded probe keeps both rare and large same-name groups responsive. Inflow first reads the filter/sort attributes and pins immutable publication versions in one repeatable-read batch. Projections of at most 100 rows include their payloads in that batch; larger projections fetch complete values only for the requested page. Filtering and tie ordering retain the HTTP contract. Every projection head uses a parameterized primary-key lookup, and cached heads are filtered before joining rows. The small-result probe uses the same bounded access path, preventing generic merge plans from walking retired publications. Published versions remain available for 15 minutes, exceeding the 10-minute frozen query lifetime. A bounded cache reuses only immutable values (32 currency/version entries, at most 50,000 selection rows and 2,000 payloads per entry); every new query still reads current heads, active membership and readiness in PostgreSQL. Price arrays retain exact decimals through lossless change-point transport. Large-result selection transfers only the 16 filter/sort columns; four social-presence bits preserve missing, NULL and empty-string filtering while page payloads retain complete URLs. Detail trader counts scan the longest window once and group each non-NULL wallet by its latest trade; the nested windows share the same exclusive end, so the exact distinct counts are preserved.
Unfiltered descending `sm_trades` queries now read current membership, heads, a count capped at 2,001, and only the requested page in one repeatable-read batch. SQL preserves float64 score ties, NULL-last ordering and canonical address text. Score/chain groups outside the requested page skip address conversion. Frozen later pages use the original publication versions for the existing 10-minute query lifetime; versions remain for 15 minutes. A bounded cache retains at most 32 complete pages of at most 100 rows each. Every new query still reads current membership, heads, readiness and the capped count in PostgreSQL; only an exact head-version match suppresses repeated page payloads. A changed or pending publication cannot reuse old values. Other filters and sort orders retain the general selection path above.

Reserved health/detail reads may start one spare after 50ms when a prepared connection is idle; ordinary bulk reads retain 100ms. Capacity and spare limits remain bounded. Losing read attempts have a bounded 150ms connection drain grace, so replies already in transit can finish without discarding prepared sessions. HTTP callers still stop waiting at their own deadline; the one-second observation cap is unchanged.

可选启动参数 `--read-cache-max-age=1s` 使管理健康和代币详情的成功观测最多保留 1 秒；默认 `0` 不启用缓存。活跃查询会在后台限并发刷新，数据库无法刷新时不返回超过时限的旧数据。响应头 `X-Data-As-Of` 保留 PostgreSQL 实际事务观测时间，不把发出查询前的等待视为数据陈旧；`X-Data-Age-Ms` 在前端代理完整接收响应后重新计算，并预留 10ms 用于本机最终套接字交付，避免返回超过 1 秒的观测。API 为本机两段交付预留 20ms，并保留原时间戳；JSON `as_of` 保留各接口原有含义。健康及详情使用额外最多 4 个连接的独立只读池，替换连接先准备语句再投入服务，批量工作保留普通连接池。启动仅准备协议语句，不执行占位查询或预填代币响应；健康报告在就绪前读取，并在服务空闲时持续刷新。每次健康刷新仍从 PostgreSQL 核对最新50条失败记录及重试状态的完整 SHA-256 内容签名；仅当前签名一致才复用载荷，内容变化及删除在同批读取新值。解析待处理量和未完成缺口的原因统计使用与写入同事务的精确计数；批量插入和删除按链与原因汇总，64 个分片分散计数写入竞争，回滚及重组删除保持总数准确。代币详情在一次可重复读批处理中计算截止时间及名称，减少一轮网络等待；有界探测为稀有和大规模同名群体选择合适的索引路径。流入查询先在一次可重复读批处理中读取筛选与排序字段，并固定不可变的发布版本；不超过 100 条的结果同批读取完整数据，较大结果仅为当前页读取完整值。筛选与同值排序保持原有契约。每个版本头按主键做参数化索引读取，缓存命中的版本头在连接数据行之前被过滤；小结果探测沿用相同读取路径，避免通用合并计划遍历已退休的历史投影。旧发布版本保留 15 分钟，覆盖冻结查询的 10 分钟有效期；有界缓存仅复用不可变值（32 个币种/版本条目、总计最多 50000 个筛选行、每条目最多 2000 个完整载荷），每个新查询仍读取 PostgreSQL 当前版本头、活跃名单和就绪状态；价格序列采用保留精确小数的无损变点传输。较大结果仅传输 16 个筛选和排序字段；4 位社交链接存在标记保留缺失、NULL 与空字符串的筛选含义，页面继续返回完整 URL。详情交易者统计只扫描一次最长窗口，按非空钱包的最后交易时间聚合；各窗口共享同一不含端点的截止时间，保持精确去重数量。

无额外筛选的 `sm_trades` 降序查询现于一次可重复读批处理中核对活跃名单、版本头、最多 2001 条的计数，并只读取当前页完整值；SQL 保留 float64 同值、NULL 末尾和规范地址文本顺序。先按分值及链分组，当前页之外的组不转换地址。冻结后续页在既有 10 分钟有效期内继续使用原发布版本，旧版本保留 15 分钟；有界缓存最多保留 32 个完整页面，每页最多 100 行；每次新查询仍在 PostgreSQL 中读取当前名单、版本头、就绪状态及限量计数，仅版本集合完全一致时省略重复载荷；版本变化或待重建时不会复用旧值。其他筛选和排序沿用上述通用路径。

健康及详情在有已准备的空闲连接时可于50ms后启动一次备用读取，普通批量读取仍等待100ms；连接及备用数量保持有界。备用慢读被取消后，隔离连接最多保留 150ms 收尾时间，允许已在传输中的响应读完并保留已准备的会话。HTTP 调用方仍按自身截止时间结束等待；观测年龄上限保持 1 秒。

PostgreSQL API (implemented and connected to the deployed frontend as of 2026-10-25): `radar api --store=pg --addr=127.0.0.1:8081` requires `RADAR_DATABASE_URL`, loads defaults or `RADAR_CONFIG`, and applies migrations at startup. `/healthz` reports database readiness. Prices, search, token details/windows/candles, activities, pools/liquidity, holdings, metadata, smart-money lists/inflow/overview/facets and admin health/retry have PostgreSQL implementations. Token smart-money cards use active-list trades for 24-hour buy/sell amounts, preserving NULL for incomplete coverage or missing prices. Missing token decimals produce a token-scoped 503 on precision-dependent routes; price candles and pools remain available. An unset `RADAR_ADMIN_TOKEN` disables PG admin routes with `401 unauthorized`; configured but missing/wrong request credentials retain `403 forbidden`. PG responses carry no mock marker. Deployment still has query timeouts, projection delays and unfinished holdings replay; process readiness is not full acceptance. Startup and frontend switching: [root README](../README.md#connecting-to-postgresql); worktrees do not deploy.

Integration tests (`internal/store`, `internal/ingest`) create a throwaway database per test on the server named by `RADAR_TEST_DATABASE_URL` and skip when it is unset; CI sets it, locally use `make -C backend test-db`.

Roles: `radar ingest|backfill|parse --chain=X`, `radar enrich`, `radar compute`, `radar prune-raw --before=YYYY-MM-DD [--chain=X]`. Endpoints, rate limits, backfill windows, price sources and retention come from the chain configuration (`internal/config/config.default.yaml`, or `--config` / `RADAR_CONFIG`); secrets only from the environment (`RADAR_DATABASE_URL`, `RADAR_PYTH_API_KEY`, …). Every role serves Prometheus metrics on `RADAR_METRICS_ADDR` (default `:9100`, `off` disables). Docker: `make ingest-up` with `RADAR_DATABASE_URL` in the repository's `.env`; `make obs-up` for Grafana. Each role takes its own advisory lock, applies migrations on start and stops cleanly on SIGINT/SIGTERM.

Layout: `cmd/radar` (entry), `migrations` (embedded SQL), `internal/store` (PostgreSQL: raw blocks, ledger, cursor, gaps), `internal/ingest` (forward and backfill followers; `jsonrpc`, `solanarpc`, `evmrpc` sources), `internal/solana` (transaction model, CPI events, PDA), `internal/evm`, `internal/parse` (fact types; decoders per protocol), `internal/parser` (parse role), `internal/chaininfo` (read-only chain lookups), `internal/prices` (price source strategies), `internal/compute`, `internal/enrich`, `internal/metrics`, `internal/config`, `internal/testdb` (throwaway test databases), `internal/api` (wire types), `internal/httpapi` (handlers, inflow snapshots, idempotency, admin auth), `internal/smlist` (list file validation), `internal/mockdata` (mock `Backend`), `internal/pgapi` (PostgreSQL `Backend`), `internal/contracttest` (response validation against the contract).
